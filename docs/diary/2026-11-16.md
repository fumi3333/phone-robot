# 2026-11-16 — phone-robot v0.4.0 問題分割・手持ちカメラ測定＋シンプル操縦＋録画/データ刷新

## 背景（v0.3.0 実機テスト後の課題整理）

v0.3.0 を Note 10+ へ導入して動作確認したところ、以下の課題が見つかった。
- 電池消耗が異常に速く、UI・マップ表示に大きなタイムラグが発生する
- 停止時に自動で Google ドライブ共有画面へ飛んでしまう
- UI に「6×5m」「24×24m」「シミュレーション」など用途が分かりにくいボタンが並び、中央マップも何を指しているか直感的に分かりにくい
- カメラ映像を同時に見ながら MP4 録画し、「こういう命令を送ったらどう変わったか」をすべてデータに残して後で見返したい
- 左・右への旋回でバネ戻りに負けて直進になりやすい
- 問題が重なりすぎているため、まずは車に載せて自律走行する前に「人が手で持って車目線で歩く測定」と「ラジコン前後左右の単体確認」へ問題を分割する方針に変更

## 本日の改修内容（v0.4.0）

1. **Android ネイティブ層（バッテリー激減・ラグ解消＋ライブカメラ＋MP4 録画）**
   - `ArCoreManager.kt`:
     - `UpdateMode.LATEST_CAMERA_IMAGE` のノンブロッキングループによる CPU/GPU 空転（秒間数千回ループ＋メインスレッド飽和）を解消するため、新規カメラフレームタイムスタンプ判定（未更新時 `Thread.sleep(8)`）とループ上限 30Hz（33ms）・ポーズ配信 30Hz 上限を追加。
     - `FlutterRenderer`（`TextureRegistry`）を使った ARCore カメラ映像のリアルタイム表示用 `SurfaceTexture` 描画（`PreviewBlitter` 約 15fps）を実装。
     - ARCore 1.44.0 標準 `RecordingConfig` / `RecordingStatus` による MP4 同時録画（`camera_recording_<runId>.mp4`）を実装。
   - `LogStorageManager.kt` / `MainActivity.kt`:
     - MP4 ファイルを `MediaStore.Downloads`（`Download/PhoneRobot/run_<id>/`）および Google ドライブ共有対象へ追加（ストリームコピー）。
     - `getCameraTextureId` / `startMp4Recording` / `stopMp4Recording` チャネルを追加。
2. **記録・制御・セッション層**
   - `run_storage.dart`: コマンド送信区間ごとの車体・センサー変化（時間・PWM・行動ラベル・移動距離・向き変化[°]・前方最小距離変化[m]）を集計する `CommandEffectSegment`（`command_effects_<runId>.csv`、JSON `commandEffects`、Markdown 一覧表）を追加。
   - `real_session.dart`:
     - 記録未開始でも常時 `grid.applyScan` で障害物マップを更新するように修正。
     - UI 通知デバウンスを 120ms → 40ms（25fps 上限）へ短縮し、ESP32 状態監視（`_linkSub`）をセンサー停止から分離。
     - 前方深度から直感的な障害物アラート（`ObstacleAlert`: 赤/橙/緑）を算出。
     - `stopAndSaveRecording` の既定を `openDriveSheet: false` へ変更し、停止時ではなく「ドライブへ送る」押下時だけ共有シートを開くよう整理。
     - 手動旋回 `jog('l'/'r')` に 150ms の先当て舵（`c,0,±255`）＋旋回 PWM 上限 `178` を実装。
   - `real_driver.dart`: `_computePulseSteer` で奇数ティックに `0` へ落とさず目標方向 `±1.0` を維持し、大舵角時は駆動を `min(cruiseDrive, 0.38)` へ抑制。
3. **UI 刷新（問題の分割）**
   - `main.dart`: 起動直後の「シミュレーション」タブを外し、`RealPage` を直接開く構成に整理。
   - `map_painter.dart`: 行単位ランレングス描画による高速化、および現在地中心拡大（`followRobot`、1m/2m 距離リング＋赤色障害物表示）を追加。
   - `real_page.dart`:
     - 最上部に「① 歩いてマップ測定（手持ち）」と「② ラジコン操縦（ボタン ⇔ フリック切替）」を配置し、詳細項目・自律走行テストを右上の「⚙ 設定」へ集約。
     - 上部に大きな障害物アラートバナー、中央にカメラ映像＋マップの 2 画面（右下ワイプのタップで主役切替＋拡大/全体切替）を配置。

## v0.5.0 — Google ドライブ実機ログ（`20261116_005440` / `20261116_005808`）解析による根本修正

本人が Note 10+ から Google ドライブへアップロードした 2 件の実機ログ（`floor_map_20261116_005808.png` / `.json` / `driving_log_20261116_005808.csv` / `driving_log_20261116_005440.csv`）を解析し、マップ崩れと前方接近誤検知の原因を特定・修正した。

### 解析で判明した原因
1. **未計測レイの 4.0m 偽自由空間バグ**: `driving_log_20261116_005808.csv` で全 35 スキャン中 34 スキャンの右端 `ray[0]` が信頼度不足による `-1.0`（`inf`）になっていた。従来 `MethodChannelDepthSource` が `-1.0` を `double.infinity` に変換し、`OccupancyGrid.applyScan` が 4.0m 先まで自由空間として白く塗り潰していたため、端末が 3cm しか動いていない 5.9 秒間で 9.13m²（30.4%）の白い扇形ノイズが描かれていた。
2. **縦持ち（Portrait）＋手持ち傾け時のセンサー軸ズレと床面誤検知**: ARCore Raw Depth は常に横長センサー座標系で返るため、縦持ちで水平 `u` 軸を走査すると「画面の上下方向」がスキャンされ、`ray[20]`（上）= `0.389m` 〜 `ray[1]`（下）= `0.305m` 〜 `ray[0]`（最下部端）= `inf` と机や手元を測っていた。さらに旧 `relativePose` が基準姿勢の傾きを保ったまま回転させており、縦持ち・下向き傾け時に水平移動・方位が狂っていた。
3. **21 本レイ間の壁の点線化**: 遠方で隣接レイの間隔が 2〜4 セル空くため、壁が 1 ドット単位の点々に見えていた。

### 修正内容（v0.5.0）
1. **未計測（`NaN`）スキップ＋連続壁セル補間**（`depth_source.dart`, `occupancy_grid.dart`）
   - 実機 ToF の `-1.0` を `double.nan` に変換して `applyScan` 時にスキップ（シミュレータの `double.infinity` 開空間は維持）。実機 CSV 35 スキャンの再生比較で、偽自由空間 948 セル（2.370m²）→ 実測領域のみの 45 セル（0.113m²）へ修正されたことを確認。
   - 隣接レイ間の距離差 `<= 0.25m` かつセル距離 `2..4` 以内の壁ヒット間を直線補間し、途切れにくい壁線として記録。
2. **重力整合 3D 逆射影方式へ刷新**（`ArCoreManager.kt`）
   - `relativePose` を ARCore ワールド水平面 `(X, Z)` 射影方式へ変更（縦持ち・横持ち・斜め構えに不変）。
   - `computeRays` で深度画素 `(u, v)` を `textureIntrinsics` + `camera.pose` 回転成分で 3D ワールド空間へ逆射影し、高さ `wy ∈ [-0.20, 0.50]`・俯角スロープ `[-0.15, 0.35]` で床・天井を除外した上で水平 ±30° の 21 ビンへ集計する方式へ全面刷新。画面の自動回転ロック状態でも縦持ち・横車載どちらも正しく水平計測できるようになった。
3. **視認性改善・デモプレビュー・自動リプレイテスト追加**（`map_painter.dart`, `real_session.dart`, `real_page.dart`, `test/drive_data_replay_test.dart`）
   - 上部障害物バナーに「左 X.Xm | 正面 X.Xm | 右 X.Xm」のリアルタイム距離バーを追加し、マップ上にカメラ視野角（±30°、半径 1.5m）の青い扇形ガイドを表示。
   - 「⚙ 設定」にワンタップで部屋の壁・障害物マップとバナー動作を確認できる「▶ 部屋マップのデモ表示（動作確認）」を追加。
   - Google ドライブ実機ログに基づくリプレイ自動テスト `drive_data_replay_test.dart` を追加し、テスト群を拡充。
