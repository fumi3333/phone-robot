# 開発日記の運用ルール

このフォルダは、会話と開発の経緯を日記として残す場所。
目的は記録。でも古い誤情報が後から「今の事実」として出てくるのは防ぐ。
そのための決め事。

## ファイル構成

- `CURRENT.md` … 「今の正」はここだけ。最初に読むのはこれ。
- `YYYY-MM-DD.md` … その日の日記。経緯の記録。

## ルール

1. 日記は追記のみ。過去の文は書き換えないし消さない。
2. 事実には状態を付ける。
   - `確定` … 本人が決めたこと、本人が言ったこと、実測したこと。
   - `暫定` … 提案・検討中。まだ決まっていない。
   - `未確認` … 推測。根拠が薄い。
3. 間違いが分かったら、元の文を直さず、新しい日付で「訂正」を書く。
   訂正された側には `訂正済み（→ 訂正先の日付）` とだけ追記する。
4. 日記と CURRENT が食い違ったら、CURRENT が勝つ。
   日記は「その時点でそう考えていた」という記録にすぎない。
5. 各項目には出どころを付ける（本人発言 / 実査 / ローカル確認の報告）。
6. AIがこの記録を読むときは、CURRENT を先に読み、日記の古い記述を
   現在の事実として引用しない。

## なぜこうするか

日記は会話の勢いで書くので、途中の案や勘違いも混ざる。
それを消すと経緯が追えなくなる。消さずに「どれが今の正か」を
1枚に集約する方が、後から読む人にもAIにも安全なため。
