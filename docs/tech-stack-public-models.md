# phone-robot 技術スタック v2 — 公開モデル中心・お手本最小化

作成: 2026-10-30 / 前提: 本人の方針「お手本（模倣学習の教師データ収集）を主軸にしない。公開モデルを入れて、86 に合わせて調整する」

## 0. 方針と正直な線引き

- 知覚層（深度・検出・自己位置）は公開モデルで「お手本ゼロ」が成立する。
- 判断層（映像→操舵の E2E）は、カメラ位置・画角・車体特性が公開モデルと違うため、完全ゼロでは実車に合わない。落とし所は2段構え:
  1. まずルールベースで「お手本ゼロで動く」状態を作る
  2. その後、公開モデルを土台に少量データ（目標20〜30分分。ゼロからの学習と比べて必要量は1桁減る）でファインチューニングする
- ステアリング方式（比例制御かオンオフか）は未確定。モデル出力は連続値で持ち、閾値変換できる設計を維持する（既存合意）。

## 1. 全体構成

```
[知覚] 公開モデル群（深度/検出/自己位置）
   ↓ 深度マップ・障害物・自己位置
[判断] ルール制御 → 公開E2Eモデルの転移学習（段階導入）
   ↓ drive, steer（連続値）
[制御] スマホ → USBシリアル 115200 → ESP32 → MX1508 → モーター×2
[記録] MP4 + 時刻同期CSV（+将来: ToF深度・ARCoreポーズ）
[学習] Colab（Google AI Pro のGPU枠）→ TFLite量子化 → スマホで推論
```

## 2. 知覚層（全部公開モデル、学習不要〜軽い適応）

| 役割 | 候補 | 備考 |
|---|---|---|
| 単眼深度 | Depth Anything V2 Small | TFLite 輸出ノートブック実装済み（リポジトリ notebooks/）。ToF 実測でスケール補正して使う |
| 実距離 | Note 10+ の ToF（DepthVision） | ARCore Depth API 経由。0.5〜5m が最も正確。静止時も取れるのが単眼との差 |
| 自己位置 | ARCore Motion Tracking（VIO） | ドリフトは走行距離の1〜5%目安。ToF の壁距離で走行中に補正する |
| 物体検出 | MediaPipe / EfficientDet-Lite 系、YOLO 系（n サイズ） | ドア・窓・障害物等の検出。YOLO はライセンス注意（下記） |
| 通路・床面 | 軽量セグメンテーション（DeepLab 系の公開モデル） | 「走れる場所」の抽出。ルール制御の入力になる |

## 3. 判断層（3段構え）

### 第1段: ルールベース制御（お手本ゼロで動く）
- 深度マップから「最も空いている方向」を選び続ける古典手法（VFH 的）。
- ToF 近接で減速・停止する2段ブレーキ（最終ラインは単純な閾値で確実に止める）。
- 役割: 実車の初走行、データ収集の下地、安全の土台。学習が育つまで運転を担当する。

### 第2段: 公開 E2E モデルの転移学習（本命）
- 土台候補: Donkey Car 系コミュニティモデル / Udacity 系データで学習した PilotNet 系アーキテクチャ / OpenBot の方策ネットワーク。
- 適応の方法:
  1. 86 のカメラ画角・高さに合わせて入力画像を切り出し・リサイズし、公開側の条件に寄せる
  2. 出力（操舵）の対応付けを 86 の実測で付け替える
  3. 少量の自車データで最終層中心にファインチューニング
- 影運転（シャドウモード）で、人間/ルールの操作とモデルの判断がズレた場面だけを自動で集め、調整用データにする。

### 第3段: 小型 VLA の検証（任意・将来）
- SmolVLA（LeRobot 系、約450M）など、安いハード向けの Vision-Language-Action モデル。
- Note 10+ の実機推論は重いため、まず Colab/PC 上の評価まで。ネイティブ化後の検討項目。

## 4. 制御層（既存資産をそのまま使う）

- 通信: USB シリアル 115200bps、コマンド形式 `c,drive,steer` ＋ 単文字コマンド（既存ファーム v2.0 系）。
- ESP32: GPIO16-19 / LEDC PWM（書き換え済み）。ウォッチドッグ 400ms、スルーレート制限は維持。
- ドライバ: MX1508（信号入力 1.8〜7V のため ESP32 の 3.3V で直接駆動可）。
- 電源: 車体は単3×6（充電池 7.2〜8.4V が安全側）。ESP32 はスマホ USB 給電。GND 共通必須。

## 5. データ層

- 形式: MP4 ＋ 時刻つきコマンド CSV（Web HUD に実装済み）。ネイティブ化後に ToF 深度と ARCore ポーズを追加し、マルチモーダル化する。
- 収集の主役はルール制御と手動の併用。お手本は「大量収集」ではなく「調整用に少量」が前提。
- 学習: Colab で学習 → TFLite int8 量子化 → スマホ側は TFLite Interpreter（NNAPI/GPU デリゲート）で推論。
- 評価: 自動採点テストコース（衝突回数・完走率・滑らかさ）で、公開モデルの素 vs 調整後を数字で比較する。

## 6. アプリ形態

- 現行の Web HUD: 実験とデータ収集用として維持。
- 本命は Flutter ネイティブ化: ARCore（Depth API＋Motion Tracking）、ToF、気圧・地磁気・IMU の一括取得のため。ブラウザではこれらに触れない。

## 7. ライセンス注意（事業化の前に必須確認）

- 公開モデルは商用条件がバラバラ。例: YOLO（Ultralytics）は AGPL 系、Depth Anything V2 はモデルサイズでライセンスが異なる、等。
- 個人の実験段階では問題になりにくいが、事業で使うモデルは採用前に必ずライセンスを確認し、必要なら商用可の代替（MediaPipe 系など Apache のもの）に差し替える。

## 8. 実装の順番

1. 第1段ルール制御で実車を走らせる（部品到着後）
2. ToF＋ARCore の取得（ネイティブ化）とドリフト補正
3. 公開 E2E モデルのオフライン評価（保存したログ映像で「当たってるか」だけ先に見る）
4. 影運転でズレ場面を集め、少量ファインチューニング
5. 自動採点コースで版管理しながら改善

## 9. 目的の更新（2026-10-30 本人決定）

- 目的を「マップを作ること」に置く。自動停止は目的ではなく、ぶつからずに回るための部品に位置づけ直す。
- 地図の表現: 占有格子地図（部屋をマス目に分け、行けた場所／壁／未探索を色分け）。
- 探索の判断: フロンティア探索（未探索との境目を次の目的地にする）。車が自分で「次にどこへ行きたいか」を決める仕組み。
- 前提: 自己位置（ARCore）が必要なため、Flutter ネイティブ化が「将来」から「次の一手」に格上げ。
- 地図の歪み対策: ToF 実測による位置補正と、同じ場所に戻った際のループクロージャ（歪みの一括補正）。
- 事業接続: 完成した地図＋異常のピン留めが、そのまま巡回レポート（学校夜間巡回の商品形）になる。
