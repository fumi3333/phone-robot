# 設計判断の記録

この文書は、phone-robot の技術と部品の選定理由を記録するものである。
結論だけでなく、なぜそう判断したかを残す。

## 頭脳：スマートフォン（Galaxy Note 10+）

- 自分の位置を出す仕組み（ARCore）と、距離を測る深度センサー（ToF）が、調整済みの形で手に入る。これを部品から自作するのが最も難しい部分である。
- 開発と検証の対象機種は Galaxy Note 10+ に固定する。機種ごとにカメラや深度の癖が違うため、まず1機種で挙動を把握する。
- 将来の対応機種は「ARCore が動作すること」を最低条件とする。深度は ToF がなくても、動きからの推定や AI の単眼推定で代替できる見込みがある。

## マイコン：ESP32（Lzxuan 製 Type-C 基板）

- スマホからの命令をモータードライバへ中継する役割に徹する。判断はスマホ側で行う。
- 使用した基板には日本の技適マークがないため、Wi-Fi / Bluetooth は有効化しない。通信は USB 有線シリアルのみとする。有線は遅延と安定性の面でも有利である。
- 候補だった Freenove 製基板は、GPIO16 に基板上の LED が接続されており、本プロジェクトの信号割り当て（GPIO16〜19）と競合するため見送った。

## モータードライバ：MX1508 から L298N へ変更

- 当初は MX1508 を選定した。信号入力が 1.8〜7V で ESP32 の 3.3V 信号をそのまま使えること、1.5A/チャンネルの出力、価格が理由である。
- その後、ハンダ付け作業を前提にしない方針に転換したため、ネジ端子で配線できる L298N モジュールへ変更した。
- L298N は約2Vの電圧降下があり、モーターへ届く電圧は下がる。室内での地図化の実験では速度より確実さを優先し、この代償を受け入れる。

## 電源：車体の単3×6本をそのまま使う

- 車体（ジョーゼン 1/16 トヨタ86）の電池ボックスを流用する。
- 充電池（ニッケル水素×6、7.2V）での運用を基本とする。アルカリ新品は無負荷で約9.6Vまで上がり、ドライバの上限に近づくためである。
- 純正の電源スイッチもそのまま流用する。

## ソフトウェア：Flutter

- Android ネイティブの機能（ARCore、USBシリアル）に直接触れる必要があるため、ブラウザではなくネイティブアプリとする。
- 開発者に Flutter / Dart の既存資産（voice_reader 等）があり、学習コストが小さい。
- 地図化の中核ロジックは機種に依存しない形で分離し、シミュレーションと実機で同一のコードを使う。将来、頭脳を別の機材に替える場合も中核は移植できる。

## 地図化：占有格子地図＋フロンティア探索

- 地図は5cm四方のマス目（占有格子地図）で表し、未探索との境目（フロンティア）を次の目的地にする。経路計画は A* による。
- 室内・低速・小規模な環境では、この古典的な構成で十分な精度が得られ、計算も軽い。
- 自己位置の推定は自作せず ARCore に委ねる。位置のズレを地図側で補正する本格的な SLAM は、難易度と開発コストの観点から現段階では見送る。シミュレーションでは、補正なしの場合に地図が崩れることを確認済みであり、これが ARCore に委ねる判断の根拠である。

## ログ形式：動画（MP4）＋時刻付き走行命令（CSV）

- 走行のたびに映像と命令を時刻で対応づけて記録する。後から学習データや検証材料として使うためである。

## アプリ配布：GitHub Releases（APK）

- 開発者の他プロジェクト（voice_reader）と同じ方式とする。ストアの審査を介さず、検証済みの版を直接配布できる。
- APK のビルドは GitHub Actions で自動化している。
