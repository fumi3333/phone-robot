# Antigravity への依頼書（2026-10-30 部品到着後）

## 背景
- 部品が到着した：ESP32 基板（Lzxuan、ESP32-D0WDQ5-V3、CH340C、USB Type-C、ASIN B0HNDRRGVZ）と MX1508 3個パック（B083DT2DMV）。
- ESP32 の缶の刻印を実物確認した結果、認証は FCC と CE のみで **技適マークは無い**。したがってこの基板では Wi-Fi / Bluetooth を有効化しないこと（現行設計は USB 有線のみで問題なし）。
- ピン配置は標準 DevKitC 型で D16〜D19 あり。ファーム（コミット 2972808 で ESP32 化済み）の割り当てがそのまま使える前提。
- 今日のゴールは「ESP32 単体テスト合格 → ファーム書き込み → シリアルでコマンドが通る確認」まで。車体側の配線・ハンダは本人の作業なので、勝手に進めないこと。

## タスク1：PC 接続と認識確認
1. ESP32 を USB Type-C ケーブルで PC に接続する。
2. デバイスマネージャーで COM ポートとして認識されるか確認する。認識されない場合は CH340 ドライバをインストールする。
3. 認識できたら、COM ポート番号を記録する。

## タスク2：単体テスト書き込み
1. Arduino IDE でボード（ESP32 Dev Module 相当）とポートを設定する。
2. 最小のテストスケッチ（シリアルに文字列を出すもの、または Blink）を書き込む。
3. 書き込み成功＋シリアルモニタで出力が見えることを確認する。
4. 失敗した場合は、エラーの全文を記録する（初期不良なら Amazon 返品判断に使う）。

## タスク3：実ファームの書き込みと疎通確認
1. `firmware/esp32_toyota86/esp32_toyota86.ino` を開き、書き込み前に次を確認する：
   - ピン割り当てが GPIO16/17/18/19 で、LEDC の PWM になっていること
   - シリアル 115200bps、コマンド形式 `"c,drive,steer\n"` と単文字 f/b/l/r/s
   - 通信途絶 400ms のウォッチドッグ
   - Wi-Fi / Bluetooth を有効化するコードが **無い** こと（あれば除去して報告）
2. 書き込む。
3. シリアルモニタから `c,50,0` や `s` 等を送り、ファーム側の応答・状態変化（ログ出力）が返ることを確認する（モーター未接続でよい）。

## タスク4：HUD との接続確認（可能なら）
1. PC の Chrome で https://fumi3333.github.io/phone-robot/ を開く。
2. Web Serial で ESP32（タスク1の COM ポート）に接続できるか確認する。
3. 画面のジョグ操作でコマンドが流れ、ファーム側に届くか確認する。

## タスク5：記録
1. `docs/diary/2026-10-30.md` に追記する（追記のみ、状態タグ 確定/暫定/未確認 と出典を付ける）：
   - 部品到着（確定）
   - 技適なし確定：缶の刻印は FCC/CE のみ（確定、出どころは実物写真）
   - タスク1〜4の結果（COM 番号、書き込み成否、疎通の可否）
2. `docs/diary/CURRENT.md` の「今の正」を更新する：部品到着済み、ESP32 テスト結果、次はモーター直結テストと配線。
3. GitHub への push は本人の明示指示がある時だけ（読み取り専用原則）。
